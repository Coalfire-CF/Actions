# Org terraform-docs standard

## Purpose

`README.md` in a Terraform module repo is generated in full from two authored
partials. One tool owns the file, the tool version is pinned by machine, authors
regenerate locally, and CI only verifies. This removes the churn that came from
two generators splicing into one hand-authored README on PR branches and both
pushing commits back.

## Scope

Applies to every Coalfire-CF repo that calls
`.github/workflows/org-terraform-docs.yml` and has a generated block in its root
`README.md`. Repos with no Terraform, or with no generated block, are out of
scope: there is nothing to generate.

Nested `README.md` files under `modules/` or `examples/` are **not** in scope by
default. See [Nested READMEs](#nested-readmes).

## Reference standard

Azure Verified Modules requirement **TFNFR2, "Module Documentation Generation"**
(severity MUST). The org config is adapted from the AVM reference config, with
three deliberate differences recorded in `templates/terraform-docs/.terraform-docs.yml`:

| Setting | AVM | Here | Why |
| ------- | --- | ---- | --- |
| `sort.by` | `required` | `name` | AVM's order would reorder every Inputs table in the fleet |
| Section order | Modules last | Modules mid | Matches what the fleet renders today |
| Lint pragmas | never re-enabled | re-enabled before the footer | AVM silently exempts its own footer from linting |

## Authoritative configuration

`templates/terraform-docs/.terraform-docs.yml` is the single source. Copy it
unchanged into a module repo root. Load-bearing keys:

```yaml
formatter: "markdown table"   # must match; see below
version: "0.20.0"             # exact, enforced by terraform-docs itself
header-from: "_header.md"
footer-from: "_footer.md"
output:
  file: README.md
  mode: replace
sort:
  enabled: true
  by: name
recursive:
  enabled: false
```

`formatter` must stay `markdown table`. The reusable workflow passes the
formatter as a subcommand, and terraform-docs ignores the config `formatter` key
whenever a subcommand is given, so a mismatch renders one thing locally and
another in CI.

`version: "0.20.0"` is exact because 0.20.0 is what CI runs (baked into
`terraform-docs/gh-actions` v1.4.1) and its output differs from 0.24.0 in table
delimiter row padding. A range pin that admits 0.24.0 makes local output disagree
with CI.

## Marker model

`output.mode: replace` wraps the whole file in the generated markers:

```text
<!-- BEGIN_TF_DOCS -->
<!-- Code generated by terraform-docs. DO NOT EDIT. Edit _header.md or _footer.md. -->
... _header.md verbatim ...
<!-- markdownlint-disable MD033 MD034 MD060 -->
... Requirements, Providers, Modules, Resources, Inputs, Outputs ...
<!-- markdownlint-enable MD033 MD034 MD060 -->
... _footer.md verbatim ...
<!-- END_TF_DOCS -->
```

The whole of `README.md` sits inside the marker pair. Exactly one `BEGIN` and one
`END` must be present. Two pairs means the README was duplicated by earlier
generator churn and needs a human before migration.

The lint pragmas are re-enabled before the footer so authored footer prose is
still linted.

## Partial-file model

| File | Contains | Edited by |
| ---- | -------- | --------- |
| `_header.md` | everything above the generated tables | authors |
| `_footer.md` | everything below the generated tables | authors |
| `README.md` | generated, in full | nobody, ever |

Both partials must exist wherever a `.terraform-docs.yml` lands.
`terraform/load.go` `loadSection` errors when `header-from` names a missing file.
An empty partial is fine; a missing one fails the render.

### Root README behavior

The migration splits the existing `README.md` at the markers:

```text
_header.md = everything strictly before <!-- BEGIN_TF_DOCS -->
_footer.md = everything strictly after  <!-- END_TF_DOCS -->
```

A README whose `BEGIN` marker is on line 1 has no header prose and gets a
0-byte `_header.md`. That is correct, not a defect.

### Nested READMEs

Measured across the fleet: of 65 nested marker READMEs in 30 repos, **64 are
regenerated by nothing at all**. Only `terraform-google-iap-ingress` passes
`recursive: true` to the caller. Because `recursive.enabled: false` in the
canonical config, nested directories receive no config and terraform-docs never
touches them, so they are left byte-untouched by the migration.

Starting to generate them is a separate decision. Any repo that sets
`recursive: true` needs `_header.md` and `_footer.md` in every submodule
directory first, or the render fails on the missing partial.

### Handwritten prose preservation

Prose lives in the partials verbatim, so a migration is reversible by reverting
the PR. The sweep additionally proves preservation: every non-blank authored line
must still be present in the regenerated README, compared after normalizing two
transformations terraform-docs applies:

- trailing whitespace is stripped
- `settings.escape: true` escapes markdown punctuation, so authored
  `coalfire_logo.png` renders as `coalfire\_logo.png`

If any authored line is missing, that repo is reported and left unpushed.

The retired `## Tree` section is dropped from `_header.md` on purpose, and is
therefore excluded from the preservation comparison.

## Required workflow path filters

`README.md` is generated from the partials and the config, so the caller must
trigger on them. Add to the caller's existing `paths:` list:

```yaml
      - "_header.md"
      - "_footer.md"
      - ".terraform-docs.yml"
```

Without these, a prose-only edit ships a stale README on a green PR and the
verify gate is decorative.

If a caller has **no** `paths:` filter at all, add nothing. It already runs on
every PR, which is a superset; adding a three-entry list would narrow it and stop
it running on `.tf` changes.

## Verify-only workflow behavior

`.github/workflows/org-terraform-docs.yml` never writes to a branch:

- `permissions: contents: read`
- `git-push: 'false'`
- `fail-on-diff: 'false'`, because it reports only "is out of date" with no diff
  and is documented as ignored whenever `git-push` is set

Drift is detected from git instead, and compared against `HEAD`:

```bash
git diff --quiet HEAD --
```

`HEAD` is load-bearing. The action runs `git add` on the rendered file for
`inject|replace` modes whether or not `git-push` is set, so a plain `git diff`
compares the worktree against an already-staged copy, finds nothing, and passes
on a stale README. This was caught by the kms pilot, where the deliberately
stale run went green.

On drift, a human PR fails with the diff and a regenerate command. Slack is not
paged, because a stale README is an authoring step that was skipped rather than
an incident.

### Dependabot behavior

Version tables move on provider bumps, and a bot cannot run a local hook, so a
Dependabot PR gets a `::warning::` and a step summary rather than a red check. A
maintainer commit, or `@dependabot rebase` after one, refreshes it.

An earlier comment in the workflow claimed a Dependabot run receives a read-only
`GITHUB_TOKEN`. That is false: a Dependabot-triggered run does receive the
permissions the caller declares (measured on run 31428925380, `contents: write`).
Pushing is withheld by choice, not by token capability.

## Pinning

Callers pin the reusable workflow to an immutable released SHA with the version as
a trailing comment:

```yaml
    uses: Coalfire-CF/Actions/.github/workflows/org-terraform-docs.yml@<40-hex-sha> # vX.Y.Z
```

Never pin a branch head or a movable tag. The sweep refuses to run in mutation
mode without a full 40-character SHA.

## Pre-commit expectations

The design assumes authors regenerate locally. Install once per clone:

```bash
pre-commit install
```

Then regenerate on demand:

```bash
pre-commit run --all-files
```

The hook runs the pinned container, not a local binary, because Homebrew ships
only the latest formula (0.24.0) and its output disagrees with CI's 0.20.0:

```bash
docker run --rm -v "$PWD:/w" -w /w \
  quay.io/terraform-docs/terraform-docs:0.20.0 markdown table -c .terraform-docs.yml .
```

Requires Docker. On macOS, Docker Desktop does not share `/tmp` by default: a
clone under `/tmp` mounts empty and terraform-docs reports a missing config while
appearing to run. Keep clones under your home directory.

## Migration process

New repos get the standard from `scripts/repo-bootstrap.sh`, which ships the
config, the hook and stub partials. The bootstrapper deliberately **skips** them
when a `README.md` already exists, because stub partials next to a real README
would make the first render replace that README and destroy the prose.

Existing repos are migrated by `scripts/terraform-docs-standard-sweep.sh`:

```bash
# plan only, the default
REPOS_FILE=/path/to/measured-list.txt \
  scripts/terraform-docs-standard-sweep.sh

# deliver
DRY_RUN=false \
ACTIONS_PIN=<40-hex-sha> ACTIONS_TAG=vX.Y.Z \
REPOS_FILE=/path/to/measured-list.txt \
  scripts/terraform-docs-standard-sweep.sh
```

Per repo it splits the README, drops the `## Tree` section, adds the config and
hook, patches the caller, regenerates with the pinned container, proves prose
preservation, then opens a PR.

The repo list is **required** and must come from a measured enumeration. Code
search is not a valid source on this fleet: it 503s mid-survey and has returned
"1 unique repo" for a query matching hundreds. Enumerate by walking
`/repos/{owner}/{repo}/contents/...` and reading each file, checking the exit
status of every call. Note `/git/trees` returns 404 for private repos here.

## Exception handling

The sweep refuses rather than guesses. Each of these leaves the repo unpushed and
reported:

| Outcome | Meaning |
| ------- | ------- |
| `MANUAL` marker count | not exactly one `BEGIN` and one `END`; usually a duplicated README |
| `MANUAL` markers reversed | `END` appears before `BEGIN` |
| `MANUAL` partial exists | `_header.md` or `_footer.md` already has content |
| `MANUAL` marker in partial | the split produced a partial containing a marker |
| `MANUAL` prose lost | an authored line is missing after the render |
| `MANUAL` recursive | caller sets `recursive: true` and has nested READMEs |
| `MANUAL` contents write | `contents: write` survived the patch |
| `SKIP` | no root `README.md`, or no generated markers |
| `COMPLIANT` | already migrated, or the render changed nothing |
| `ERROR` | clone, render, commit, push or PR creation failed |
| `WOULD-MIGRATE` | dry-run success; this repo is ready to deliver |
| `OPENED` | PR created |
| `PR-EXISTS` | branch already had an open PR, left alone |

Every target lands in exactly one outcome, and the run fails if the recorded
count does not equal the targeted count.

## Validation commands

```bash
# the sweep's own unit tests, each mutation-proved
bash tests/terraform-docs-sweep.test.sh

# the bootstrapper, including the existing-README guard
bash tests/repo-bootstrap.test.sh

# lint a migrated repo with the version CI runs
npx markdownlint-cli2@0.23.0 README.md _header.md _footer.md

# confirm a clone is current without pushing anything
docker run --rm -v "$PWD:/w" -w /w \
  quay.io/terraform-docs/terraform-docs:0.20.0 markdown table -c .terraform-docs.yml .
git diff --quiet HEAD -- && echo current || echo stale
```

## Markdown lint policy

Generated tables contain inline HTML anchors, bare URLs and unpadded table
delimiters, which is why MD033, MD034 and MD060 were disabled fleet-wide. The
pragmas inside the generated block now exempt exactly that content, so the rules
are enforced again for authored prose.

The policy exists in two places and they must stay in sync:

- `.markdownlint-cli2.jsonc`
- the heredoc in `.github/workflows/org-markdown-lint.yml`

CI runs `markdownlint-cli2` 0.23.0. Census with that version, not the 0.23.2 that
`package.json` pins, or the result does not describe CI.

## Tree workflow retirement

`org-tree-readme.yml` was the second writer. It is now a no-op that preserves its
`workflow_call` interface so callers stay green while their caller files are
removed by `scripts/tree-readme-remove-sweep.sh`. The reusable and the Actions
self-caller are deleted only after the caller count is re-measured at zero.

The `## Tree` section is dropped from `_header.md` during the split, so migrated
repos lose it as an expected side effect. The repo file tree is visible in the
GitHub file browser and every IDE.

## Ownership and maintenance

Owned by the Actions repo. Changes to the standard mean changing
`templates/terraform-docs/.terraform-docs.yml` and releasing, after which repos
pick it up by re-pinning.

Moving off terraform-docs 0.20.0 needs a route around
`terraform-docs/gh-actions`, whose latest release pins 0.20.0. The upstream PRs
that would fix the MD060 delimiter padding (#164, #168) are unmerged. Until then,
0.20.0 is the version, and the container pin is what keeps local output equal to
CI.
